### 1. Crush "huge spew" diagnosed — auto-compaction loop, not the model

The operator's Crush sessions answered every prompt with a "summary of our
conversation" blob. Crush's session DB showed every assistant turn flagged
`is_summary_message`: auto-compaction fired on every turn because the
`context_window` in the Crush config had been halved below the local
llama.cpp server's real per-slot context (`/slots` is authoritative; `/props`
`n_ctx` is already per-slot — do not divide by `total_slots`). Restored the
window and `default_max_tokens`; verified from the log after the operator's
relaunch. Two of my own claims were wrong along the way (slot size, "skills
still failing") and corrected on operator challenge — lesson: check
`/slots`, and check log timestamps against file mtimes before calling a
logged problem current.

### 3. Main CI red → green — Issues #316, #317, PR #318 (merged)

Six tests failed on every CI run since the morning's merges. Root causes,
each verified by running it: a DNS test chased the developer's gitignored
Technitium server file (and named a real server in a public test); `opskit
doctor` failed on advisory warnings, its `--prune` used an invalid
`git branch --grep`, and it reported the main checkout as a stale worktree.
Fix: `TECHNITIUM_SERVERS_FILE` pinned in the test env; doctor gets a
fail/warn split with `--strict` (now used by `install.sh --check`), repaired
`--prune` checks with a unit-tested porcelain parser, machine-independent
tests (`HOME` and `PROXMOX_TENANTS_FILE` isolated). One PR for both because
each alone left CI red. Merged on fully green CI; main's run on the merge is
green.
