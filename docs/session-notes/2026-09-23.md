### 1. MCP-server critique and cleanup (#382–#389)

Operator asked for a constructively critical review of every MCP server wired
into OpenCode/Crush, with vikunja and DocWright (`dw-vault`/`dw-upstream`)
already marked for removal. Findings and actions:

- **vikunja** — finished a teardown left half-done from a prior session:
  removed the `vikunja` entry from `mcp/external-servers.json`, added
  `docs/kb/vikunja-mcp-update-wipes-fields.md` documenting the underlying
  Vikunja API quirk (POST replaces the whole task, no PATCH) for anyone
  touching the API directly later. **PR #383** (issue #382).
- **DocWright** — `dw-vault`/`dw-upstream` were `disabled: true` in OpenCode's
  config but never fully removed; deleted both entries (config + repo's
  `tools` withholding map + the test asserting they must be withheld).
  **PR #385** (issue #384).
- **GitHub MCP** — initially recommended dropping it entirely in favor of
  `gh` CLI; reconsidered after pushback and research. The real problem was an
  unscoped remote endpoint (~44 tools, ~61k tokens), not the concept — GitHub's
  own `github-mcp-server` supports `GITHUB_TOOLSETS` scoping. Self-hosted a
  locally-built binary (`go install .../github-mcp-server`, later pinned to
  v1.12.2 instead of `@latest` per a reliability check) scoped to
  `context,issues,pull_requests,repos`. `gh` CLI stays the default everywhere
  else. **PR #387** (issue #386).
- **Web search (`hound-mcp`)** — deeper research found the incumbent
  (`dondai44423/master-fetch`) legitimate but young/single-maintainer; its own
  Rust rewrite `donsetch` is faster and keeps the same TTL cache. Bigger
  finding: neither needs to be an MCP server at all — both ship their own
  CLI, so a skill shelling out directly gives every runtime (including Claude
  Code, which had zero self-hosted search before) the capability at zero
  schema cost. Installed `donsetch`, removed the `hound` MCP entry, wrote the
  `websearch` skill.
- **Technitium/Proxmox/erpnext/bitwarden** — kept the existing vault-launched
  custom servers; researched and rejected `Slyke/mcp-technitium-dns` as a
  replacement (single-contributor, 4-commit, zero-release project — not
  worth the operational cost of a new local HTTP daemon + new tokens for a
  production-DNS-facing tool). Real fix found instead: `bin/mcp-call.py` is a
  generic MCP-client-over-CLI shim, not mikromcp-specific, but Technitium and
  Proxmox never got the `routeros`-style bridge — meaning Claude Code had no
  sanctioned path to either. Added `technitium-dns` and `proxmox-cli` skills.
  **PR #389** (issue #388), live-probed against real servers before merge.
