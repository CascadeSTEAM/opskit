### 1. Task-level execution workflow — Issue #282, PR #283 (merged `f3e5ac1`)

Replaced the **Git & GitHub Workflow** section of AGENTS.md with a granular,
mandatory **task-level execution cycle** as the new primary workflow. The old
workflow is preserved verbatim as a backup sub-section.

New primary cycle:

1. Sync (`git fetch --all --prune && git pull`)
2. Worktree via `bin/fix-issue.sh setup <n>` (primary checkout stays on `main`)
3. Planning discussion with the human
4. Write `##PLAN` in the worktree-reserved `RESUME.md` (gitignored); critique
   it for security, appropriateness, stability, maintainability, effectiveness,
   value; write critiques into the plan section
5. Resolve flaws one by one — propose solutions for the human to choose/edit,
   update the section, remove the flaw content, repeat
6. Ask the human to review; wait for approval/edit
7. Push the plan to `plans/` (per lifecycle rules) and to the GitHub Issue as
   the public tracking surface
8. Task cycle: mark next task in progress → **TDD** (tests before code, commit
   tests first) → build and validate per task → mark "review" → loop
9. Validate new code with targeted tests; on failure update issue + plan, return
   to step 5
10. Full test suite (`make test`, `bash -n`, functional check); on failure record
   the bug in plan + issue and restart at step 5
11. Create PR that closes the issue (`Closes #<n>`); ask human: review or auto-merge
12. If auto-merge: full review of the PR, write the review in the **user's voice**
    (concise, direct, no hedging), fix non-trivial issues, merge
13. Refresh local main branch

Also added: **Trivial changes exemption** (typo/whitespace/formatting-only skip
the full cycle) and a **Voice-Matched Review** note (future: dynamic
writing-sample gathering for tone modeling).

PR #283 was auto-merged after a review written in the user's voice. One
non-trivial fix found during review: date attribution on the new primary cycle
was incorrectly 2026-07-20 at first; corrected to 2026-08-28.
