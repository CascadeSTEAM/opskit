### 4. PERMANENT FIX: skill→command drift detection and automation

**Root cause (the real one):** Opencode has TWO completely separate discovery mechanisms:
- **Skills**: `.opencode/skills/<name>/SKILL.md` — auto-discovered, triggered by `triggers:` frontmatter
- **Slash commands**: `.opencode/command/<name>.md` — explicit file, file stem = command name

A skill with `/command` in its `triggers:` does **NOT** automatically get a slash command. The file `.opencode/command/<name>.md` must be created separately. This has caused repeated session waste across multiple sessions because:
1. Agents hand-edited `.opencode/command/<name>.md` files each time
2. No automated check existed to detect missing command files
3. The skill-builder agent had no documentation about this distinction

**What was built (permanent fix):**
- `collab_skill_command_drift()` — MCP tool that detects skills with slash triggers but no command file
- `collab_create_commands(skill_names)` — auto-generates `.opencode/command/<name>.md` from skill metadata
- Added drift check to `collab_propose_improvements()` — now surfaces missing commands automatically
- Updated `agents/skill-builder.md` with critical documentation about the skills vs commands distinction
- 7 new tests for the collab tools

**Auto-generated command files:**
- `gh.md` — had slash triggers (`/gh`) but no command file
- `grind.md` — had slash triggers (`/grind`, `/plow`, `/resume`) but no command file  
- `helpdesk-ticket.md` — had slash triggers (`/ticket`, `/tickets`) but no command file

**After this fix:** `collab_skill_command_drift` shows `skills_needing_command_file: []` and `ok: true`.
